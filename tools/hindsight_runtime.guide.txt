Hindsight runtime for the memory service

tools/hindsight_runtime install provisions what the always-on memory service
(.agents/rules/memory.md, docs/runbooks/memory-service.md) runs, in the primary
checkout's work/hindsight-runtime/; every linked checkout shares it, never
install per worktree:

1. a Python 3.14 environment with hindsight-api-slim[local-onnx,embedded-db]
   1.2.3, from SHA-256-pinned PyPI wheels;
2. the pinned public CPU ONNX snapshots (embedding and reranker models);
3. PostgreSQL 18.1.0 with pgvector 0.8.5 in pg0-install/. The build is bundled
   inside the pg0 binary of the hash-pinned pg0-embedded wheel, so nothing more
   is downloaded: install starts a throwaway pg0 instance once, which extracts
   it, stops and drops that instance (no database or server is left), and
   checks the extracted tree against the digest pinned in the launcher, plus
   the four binaries the service needs and the version. Later installs only
   verify it.

The install stamp (wheels.sha256) is written only after all three verify.

The lock records one SHA-256-verified PyPI wheel per dependency and supports
Linux x86_64, glibc 2.35 or later and CPython at /usr/bin/python3.14; uv
installs it. The host needs Bash, Git, uv and standard Linux utilities. Run
bash tools/storage_report.sh first; installation stops above the repository's
30 GiB floor, at a 31 GiB tripwire. For an explicit alternate asset root under
the primary checkout's work/, create an owner-only directory and set
ICARUS_HINDSIGHT_ASSETS_ROOT.

The service holds a shared lock on assets.lock while it runs, so install
refuses until it stops. Run install again whenever
tools/hindsight_runtime.requirements.txt changes:

python3 -m tools.memory service stop
tools/hindsight_runtime install
python3 -m tools.memory service start

Nothing here starts a server, configures a model provider or registers a
client: python3 -m tools.memory service manages the instance and the memory
MCP server is the client interface.
